# LAV SMS — isolated Render demo deployment

> **Demo only**. The upstream Laravel 8 application is out of security support and has legacy access-control patterns; conduct a full review and framework upgrade before any real student/parent records are entered.

## What this branch sets up
- Dockerized Laravel app behind Apache serving only the `public/` directory on port 10000.
- Internal-only MySQL 8 as a Render **paid private service** with a paid persistent disk.
- MySQL is not exposed publicly.
- No secrets in Git. APP_KEY and DEMO_SEED_PASSWORD are manual Render Blueprint values; MySQL secrets are generated by Render.
- First-start migration and one-time synthetic seed; subsequent restarts don't overwrite records.
- Registration/password-reset routes disabled for public demo; default passwords in seed data replaced with an operator-provided secret.
- `.env` stays ignored.

## Prepare secrets
Generate a Laravel key on a trusted machine:
`php -r 'echo "base64:".base64_encode(random_bytes(32)).PHP_EOL;'`
Set as `APP_KEY` during initial Blueprint approval.
Choose a **different** random 20+ character string for `DEMO_SEED_PASSWORD` to access the seeded sample accounts. Never reuse a real account password.

## Deploy
1. Review `render.yaml` costs, including private MySQL compute and disk.
2. Create Render Blueprint from this branch in the intended workspace.
3. Approve only after confirming costs. Enter the two manual secret values in the Render dashboard.
4. Monitor DB startup, web build/deploy and app logs.
5. Confirm the login page, admin/parent/student demo logins, class records, fee receipts and marksheets.
6. Change sample institution branding and disable unused modules before showing schools.

## Local Docker
Copy `.env.example` to `.env`. Set `APP_KEY` (base64), `DB_PASSWORD`, `MYSQL_ROOT_PASSWORD`, `DEMO_SEED=true` and `DEMO_SEED_PASSWORD` (long random). Then `docker compose up --build`. Visit http://localhost:8000.

## Limitations
- **Not yet security audited**; additional user permissions, file upload safety, and PIN/marksheet authorization need full tests.
- Render Free web instances can sleep; filesystem uploads and session files are ephemeral.
- The MySQL private service and disk are billed. Do not deploy this Blueprint without reviewing costs.
- Never enter real children/student personal data in this demo.
